## 3. Surviving canonical responsibilities

### A. Evidence integrity / lineage

One bounded contract composes observation/inference separation, construct validity, reference-class freeze, selection lineage, intervention history, material context and abstraction/scope binding.

Hard boundaries include:

- `OBSERVATION != INTERPRETATION`
- `GATE_PASS != UNMEASURED_PROPERTY`
- `COMPARATOR_SHIFT != PERFORMANCE_IMPROVEMENT`
- `SELECTED_COHORT_EVIDENCE != POPULATION_EVIDENCE`
- `POST_INTERVENTION_STATE != INTRINSIC_BASELINE_PROPERTY`
- `ABSTRACT_SUCCESS != REFUTATION_OF_CONCRETE_FAILURE`

This does not become an analytics platform. It validates evidence claims supplied by replaceable observers.

### B. Derived-artifact freshness

A derived artifact is revision-bound to the upstream fields it consumed.

`UPSTREAM CHANGE != DOWNSTREAM FRESHNESS`

Only affected dependency slices become stale. Unrelated changes do not cause a global rebuild. A stale artifact must be recomputed or boundedly revalidated before consequential reuse.

### C. Typed smallest-gate re-entry

After externally established stage + causality evidence:

```text
DISCOVERY          -> DISCOVERY_REFRESH
IMPLEMENTATION     -> DA_COUNTER_DA
DEPLOYMENT         -> DEPLOYMENT_IDENTITY
POST_DEPLOY_METRIC -> POST_DEPLOY_DEBUG
UNKNOWN/CORRELATED -> ANALYSIS_REOPEN
```

The binder owns routing only.

`CORRELATION != ROOT CAUSE`

### D. Human Gate agency preservation

When authority is explicitly sourced from a human choice, a mere click is insufficient. The current human needs a visible refusal path, material-consequence disclosure, a current explicit decision and non-coercive choice architecture.

`CHOICE_PRESENTATION != MEANINGFUL_AUTHORIZATION`

This is applicability-bounded: it does not require every authority mechanism to be a UI.

### E. Decision succession separate from PHOENIX recovery

`RECOVERY != DECISION SUCCESSION`

`RETRIEVAL != DECISION COMPETENCE`

PHOENIX_READY remains regeneration/recovery evidence. A separate decision-succession state requires held-out decisions, authority compliance, escalation/UNKNOWN discipline and creator absence. It grants no authority.

## 4. Connection design

The surviving responsibilities are implemented in a side-effect-free `integrity.py` binder and connected through `lifecycle.py`.

The integration deliberately does **not** add new lifecycle states for every guard. The existing sequence remains authoritative.

`integrity.py` returns:

- evidence-integrity state;
- selective derived-artifact freshness;
- Human Gate integrity state;
- typed re-entry route;
- decision-succession state.

`lifecycle.py` consumes applicable blocking states before an otherwise eligible consequential transition. Legacy workloads without the new optional evidence profiles retain their existing behavior.

A proven local failure exposes the smallest existing `reentry_route`; uncertain causality returns to `BUILD / ANALYSIS_REOPEN` rather than guessing.
