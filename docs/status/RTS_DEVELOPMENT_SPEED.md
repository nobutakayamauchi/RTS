# RTS 開発速度ベースライン

## 結論

```text
HIGH_VELOCITY_GOVERNED_SOLO_AI_DEVELOPMENT
```

この評価は、コード出力だけではなく、証拠固定、権限境界、失敗系テスト、CI、ロールバック、説明資料を含む直近4工程の観測値に基づく。

## 測定方法

### PRゲート時間

GitHubの `created_at` から `merged_at` まで。

PRを開いた後のCI、修正、レビュー、マージを含む。PRを開く前の設計・実装時間は含まない。

### 工程間時間

直前の限定工程がマージされてから、次の限定工程がマージされるまで。

会話、設計、実装、CI、工程内の待ち時間を含む。純粋な手作業時間やモデル計算時間を分離した数字ではない。

## どの程度のものを、どの程度で作れたか

### 限定評価・判断モジュール

観測レンジ: **約20〜30分／工程**

成果物の例:

- 重み付き完成度評価
- リスク台帳
- 次工程計画
- 指示文の表示・監査方針
- 失敗時停止テスト

### ガバナンス付き運用・レビュー機能

観測レンジ: **約21〜25分／工程**

成果物の例:

- 10〜15ファイル
- 約500〜600追加行
- 7段階の運用手順
- 固定受付契約
- 4段階エスカレーション
- 読者テストと追記型修正
- 専用CIと失敗系テスト

### 複数案件の完全再現パッケージ

観測値: **約44分／工程**

成果物の例:

- 8成果物
- 2回生成の決定性確認
- 10次元比較
- 12基準の審査
- 受入判断
- 全体回帰CI
- 1,800行超の追加

## アピールに使える表現

> AIを使ってコードだけを速く書くのではなく、証拠、権限、停止条件、テスト、CI、ロールバックまで含む限定工程を、直近の観測では中央値約24分半の工程間隔で完成・マージしています。最大規模の複数案件再現工程でも約44分でした。

## 境界

- 4工程の内部観測であり、将来の納期保証ではない。
- 未知の外部API、顧客調整、法務、外部人間レビューは別途時間が必要。
- 行数は概念的難易度を直接表さず、1行JSONは実データ量を過小表示する。
- 品質はCI成功、失敗系テスト、権限境界、証拠バインドとセットで評価する。
