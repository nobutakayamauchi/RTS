# Reconnect Project — Full Context v1

## 1. Project thesis

能力、努力、判断、成果が存在しても、本人が価値として認識できない、証拠が散らばる、他者へ説明できない、適切な場所へ届かない、必要な資源が不足することで、社会・仕事・事業へ接続されないことがある。

```text
埋もれた活動・判断・成果
→ 証拠との結合
→ 価値の翻訳
→ 人間による承認
→ 公開物・提案物
→ 顧客・協力者・企業・機会・支援との接続
→ 接続後の行動と結果の記録
→ 次に必要な資源・機会の学習
```

最終目的は社会再接続。最初のMVPは価値発見・証拠化・伝達に限定する。

## 2. Canonical narrative

> 埋もれた成果を発見する。価値を他者に伝える。必要な場所へ接続する。接続後の変化を記録する。本当に必要な支援を学習する。最終的に、社会参加・再挑戦を支える仕組みにする。

## 3. Problems

1. GitHub、PR、仕様、テスト、開発ログに成果があるが、価値として認識・説明されない。
2. AI協働開発では、人間の問題設定、設計、制約、監査、優先順位、承認が「AIが作った」で消えやすい。
3. 技術成果を顧客、採用、協業、支援向けの言葉へ変換できない。
4. 公開と営業が弱く、開発しても市場接続が起きない。
5. 機材、信用、情報、機会の不足が能力発現を止める。
6. 支援側も、何をどの順番で渡せば変化するか判断できない。
7. 顧客がない状態では開発だけが可視的進捗になりやすい。

## 4. Users

### Core

- AIで成果を出しているが価値を説明できない個人
- 仕様、制約、監査、意思決定で開発を動かす人
- GitHubや業務ログに成果が埋もれている個人開発者
- 少人数組織、個人事業、小規模チーム

### Validation

- 顧客、採用担当、協業先、支援者、スポンサー
- AI人材の実務貢献を把握したい企業
- 開発資産や履歴を整理したい組織

### Future

- 就労・再挑戦支援組織
- 公共機関、教育、福祉
- 人材、案件、支援マッチング基盤

## 5. Product stages

1. Discover — 活動、判断、制約、成果、失敗回避を抽出
2. Evidence — コミット、PR、テスト、仕様、レビューへ結合
3. Translate — 顧客価値、採用価値、協業価値、社会価値へ翻訳
4. Decide — 人間が承認、修正、却下、非公開を判断
5. Connect — 手動で公開、提案、問い合わせ
6. Observe — 接続前後の行動、成果、外部反応を記録
7. Learn support fit — 不足資源、提供、変化、次の不足を学習

## 8. Separate lanes

- Implementation WIP — 常に一件
- Immediate cash lane — 最初の有料商品と手動営業
- Funding and grants lane — 制度、期限、対象経費を別管理
- Public evidence lane — ログ、成果、テスト、問い合わせ入口

## 9. Confirmed strategic decisions

1. このプロジェクトをLoop Engineの実戦負荷として使い、進行しながらエンジンを磨く。
2. 全体像は最初に描くが、実装は一本ずつ。
3. Master Product SpecificationとMVP Implementation Contractを分離する。
4. 開発過程自体を能力と成果の証拠へ変換する。
5. 最初にキャッシュポイントを作る。
6. 助成金、補助金、資金調達は別レーン。
7. 自動SNS投稿、自動営業、自動契約は初期範囲外。
8. 困窮事情ではなく仕様、ログ、GitHub、テスト、成果物で評価可能にする。
9. CASE-001の生活事情は内部文脈。公開は人間承認制。
10. 社会再接続は最終目的。初期MVPは価値発見、証拠化、伝達、接続入口。
11. 人間を所有、格付け、拘束する仕組みにしない。
12. 支援の適合性は提供前後の行動と成果で検証する。
13. 一事例を一般的な有効性の証明としない。

## 11. Canonical records

## 12. Evidence labels

- VERIFIED — 正確なコミット済み、または独立確認可能
- INFERRED — 証拠に基づく解釈
- SELF_REPORTED — 本人申告、独立未確認
- UNVERIFIED — 証拠不足
- CONFLICTED — 信頼可能な記録が競合

## 13. Human contribution dimensions

問題設定、目標選択、制約設計、アーキテクチャ、仕様、AI指示、受入条件、リスク検出、レビュー、却下、優先順位、統合、障害復旧、最終承認。

AI、ツール、協力者、既存OSSの貢献は別記録にする。

## 14. Human-only authority

承認、修正、却下、失効、置換、公開、非公開、営業、応募、問い合わせ、注文・支援・契約受諾、個人情報開示、新Scope開始、プロバイダー・リポジトリ権限拡大、商業優先順位。

## 15. Privacy classes

- PUBLIC — 人間承認済み成果、仕様、テスト、説明
- INTERNAL — 未承認候補、判断、評価
- SENSITIVE — 健康、家族、雇用、法務、財務、住所、連絡先、非公開リポジトリ、第三者情報
- PROHIBITED — パスワード、秘密鍵、認証情報、未同意第三者情報

公開文章は事実、推論、本人申告、未検証を混ぜない。生活事情で価値を代替しない。

## 17. CASE-001 internal context

- 開発者は、コード一からの記述より、目的、仕様、制約、優先順位、AI指示、検証、監査、承認を担う。
- 開発はスマートフォンとVPS中心。
- 複数のRTS関連リポジトリ、仕様、テスト、PR、ログが存在。
- 自分の成果を過小評価しやすく、外部説明と営業がボトルネック。
- 顧客・市場反応は限定的で、キャッシュポイントを早く作る必要がある。
- 開発・生活環境に制約があり、停止・再開・チェックポイントが重要。

健康、家族、雇用、法的手続、詳細財務、居場所、勤務先、第三者の行為は公開成果へ入れない。

## 18. P0 test protocol

Execution order:

1. Source digest
2. Master Overview
3. Possibility Atlas
4. Scope Cut Matrix
5. Canonical Records / Authority / Privacy
6. Contradiction and Unknowns Audit
7. Recommended First Slice
8. Human Review Packet
9. Checkpoint and stop

Pass conditions:

- 必須成果物が存在
- 主張に証拠区分
- 将来枝に状態と解凍条件
- 一つのSliceを推奨するが自動承認しない
- 公開・内部・センシティブの境界
- 実装・外部行動なし
- 再開地点が決定的

Failure classes: SCOPE_DRIFT / LOST_WHOLE / FALSE_CLOSURE / EVIDENCE_GAP / PRIVACY_LEAK / AUTO_APPROVAL / WIP_BREACH / REPEAT_FAILURE / NON_RESUMABLE / OVER_GOVERNED.

## 19. Scope-cut recommendation

Default recommendation:

```text
P0_SCOPE_CUT
→ P1_MASTER_SPEC
→ P3_VALUE_DISCOVERY_MVP
```

The first P3 vertical slice uses one fixed RTS repository or PR set and produces at least 10 evidence-linked achievement candidates, contribution maps, evidence labels, value translation, exaggeration rejection, and one public-asset draft.

P2 public evidence and P4 manual service should reuse the first approved P3 output. If immediate cash is the overriding constraint, a minimal P2 and service-first P4 path may be chosen after P1.

## 20. Human gate

Allowed decisions:

APPROVE_P1 / APPROVE_P1_P2 / APPROVE_P1_P3 / APPROVE_P1_P4 / RETURN_FOR_REVISION / FREEZE / REJECT.

Required fields: selected path, maximum scope, first audience, first paid product, public disclosure boundary, project name, accepted risks, frozen branches, next review point, reason.

No human-gate decision automatically grants publication, outreach, contracts, provider use, external execution, repository writes, human ranking, or disclosure of sensitive CASE-001 details.
